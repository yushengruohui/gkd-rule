# GKD Rule Authoring

Use this guide when adding or repairing subscription rules. The goal is to
remove confirmed ads or interruptions without affecting normal user actions.

## Scope

- Edit sources in `src/`: `subscription.ts`, `categories.ts`,
  `globalGroups.ts`, and `apps/<Android package>.ts`.
- Keep each app rule in its exact package-name file and use the same package ID.
- `dist/` is generated by `pnpm build`; never edit it manually.

## Evidence and validation

Before changing a selector, reproduce the screen on a real device. Record the
app and Android versions, entry path, expected action, and current activity.
Save an accessible GKD snapshot URL for every target rule, then inspect its
screenshot and node tree. A screenshot alone is insufficient: base selectors
on node attributes, hierarchy, visibility, and `activityId`.

Test the smallest app object first in the inspector's in-memory subscription.
Confirm the intended click and verify nearby, search, settings, and subsequent
screens do not trigger. Re-test after every correction. In-memory rules are
temporary and do not replace committed source rules.

## Selector design

- Prefer unique, stable `id`, `vid`, or `desc`; use text only with explicit
  context. Use structural, size, index, or coordinate conditions only as a
  last resort.
- Narrow `activityIds` whenever known. Select only the intended clickable node
  and add parent, sibling, or visibility constraints where needed.
- Never match generic close, cancel, or skip labels by themselves, or use broad
  short regular expressions.
- Add `excludeMatches` only with snapshots showing the false positive and
  evidence that the exclusion preserves the target screen. Store those URLs in
  `excludeSnapshotUrls`.
- Use `matches` for one selector or an ordered sequence. Use `anyMatches` for
  genuine alternatives; do not combine unrelated selectors to increase reach.
- Keep group and rule `key` values stable and unique. For ordered multi-step
  flows, give every step a stable key and declare its dependencies with
  `preKeys`, so later actions cannot run out of context.

## Shared configuration

Prefer app-local groups. Add a category only when no existing category fits;
its key must remain stable and unique. Default-enable only well-evidenced,
low-ambiguity rules such as confirmed launch ads. Keep update prompts,
permissions, feature automation, local ads, and ambiguous actions opt-in.

Put a rule in `globalGroups.ts` only when it has a stable common structure,
positive and negative snapshots, and real-device verification across multiple
apps. A selector observed in one app, especially a close or skip label, is not
a global rule.

## Before handoff

Run `pnpm check`. Review the diff with `git diff --check` and the focused file
diff. Preserve unrelated working-tree changes. Commit only the completed,
single-app or single-topic change; do not stage editor files, caches, or other
agents' work.
